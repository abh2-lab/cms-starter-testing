1 · Which system am I in?

Read this before touching anything. This theme contains two disjoint design systems. Only one of them is PING.

The trap. #d34135 (50 uses) and #121212 (36 uses) are the 3rd and 4th most common colours in this theme — and neither belongs to PING. They are the leftover “Decode” editorial skin. If you open a random block for reference you have a good chance of copying the wrong palette, a hard-coded 1440px container, and a pile of literal font sizes.

Mobile (≤768px)

One breakpoint rewrites the scale, in :root. Blocks must not restate heading sizes in their own media queries — that is already handled here.

--fs-display is never used on its own. All six consumers write calc(var(--fs-display) + 16px), so the token always reads 14px smaller than what lands on screen: 74 → 90px on desktop, 32 → 48px on a phone. Read the token and you will mis-size the stat.
Not shrunk on mobile: --fs-sm, --fs-xs and --gutter. --fs-sm in particular must stay 16px — every orange pill on the site is calc(var(--fs-sm) + 1px), the header CTA included.
The phone scale is the one that matters. Most PING visitors are on a phone, so these values are set against how a native app reads — they are not the desktop scale shrunk proportionally. Two knock-on effects to remember when you change --fs-h2 or --fs-h3: the section kicker is calc(var(--fs-h2) - 4px) and the stat label is calc(var(--fs-h3) - 2px), so each token moves two things.

Font

Figtree is the only web font loaded, as a variable font (weights 300–900, roman + italic) from Google Fonts, via app.head.link in themes/default/nuxt.config.ts. The family is hard-coded in theme.css’s body rule — there is no --font-* token, so a font swap means editing two files.

6 · Components

Live examples — rendered with the same recipes the real blocks use, so what you see here is what ships.

The container

One global class, .container-custom, defined only in theme.css. Content caps at --container and gutters at --gutter below that. 

.container-custom {
  width: min(100% - (var(--gutter) * 2), var(--container));
  margin-inline: auto;
}
Never re-declare this in a block’s scoped style. <style scoped> cannot be shared, so every block that redeclared it got its own private copy — 19 of them, disagreeing on 40px vs 64px gutters. That is why the header never lined up with the page content. Put the class in the markup; keep only your own layout (grid/gap) in the scoped style.

Full-bleed band

The <section> owns the background and the vertical rhythm and spans the viewport; an inner wrapper carries .container-custom. 43 sites across 35 files use this — it is the layout idiom. 

<section class="xx">
  <div class="container-custom xx-inner">…</div>
</section>

.xx { background: #0f2d96; padding: var(--section-y) 0; }
.xx-inner { display: grid; gap: var(--space-9); }   /* layout only — no width! */

The circled-plus motif

A navy ring with the plus drawn as two bars — used by .hw-plus, .sc-plus, .fq-icon (which rotates 45° into a cross when open) and .tg-plus (a 34px scale-down). Reuse it; don’t invent another.

.plus::before, .plus::after { content: ''; position: absolute; background: #0f2d96; }

7 · Build a new block

The skeleton. Generate the pair with pnpm gen:block (it wires both registries), then fill in this shape. 

<template>
  <section class="xx">
    <div class="container-custom xx-inner">
      <p  class="xx-eyebrow">{{ eyebrow }}</p>
      <h2 class="xx-title">{{ title }}</h2>
      <p  class="xx-body">{{ body }}</p>
      <NuxtLink :to="ctaUrl" class="xx-cta">{{ ctaLabel }}</NuxtLink>
    </div>
  </section>
</template>

<style scoped>
.xx        { background: #ffffff; padding: var(--section-y) 0; }  /* never a width here */
.xx-inner  { display: grid; gap: var(--space-9); }               /* layout only */

.xx-eyebrow { font-size: var(--fs-xs); font-weight: var(--fw-semibold);
              text-transform: uppercase; letter-spacing: 0.04em;
              margin: 0 0 var(--space-3); }
.xx-title   { font-size: var(--fs-h2); font-weight: var(--fw-bold);
              line-height: var(--lh-tight); margin: 0 0 var(--space-5); }
.xx-body    { font-size: var(--fs-body); line-height: var(--lh-body);
              margin: 0 0 var(--space-6); }

/* stat pair */
.xx-stat       { font-size: calc(var(--fs-display) + 16px); font-weight: var(--fw-bold); line-height: 1; }
.xx-stat-label { font-size: calc(var(--fs-h3) - 2px); line-height: var(--lh-snug); }

.xx-cta { display: inline-flex; align-items: center;
          background: #ff6a4d; color: #fff; border-radius: 999px;
          font-size: calc(var(--fs-sm) + 1px); font-weight: var(--fw-semibold);
          padding: calc(var(--space-3) - 1px) calc(var(--space-8) + 4px);
          text-decoration: none; transition: background 0.2s; }
.xx-cta:hover { background: #e0532f; }

@media (max-width: 768px) {          /* layout only — the scale shrinks itself */
  .xx-inner { grid-template-columns: 1fr; }
}
</style>
Two eyebrow flavours. An uppercase micro-eyebrow (--fs-xs, letter-spaced) as above — or, on the shield page, a sentence-case section kicker at calc(var(--fs-h2) - 4px). Don’t mix them up: “How it works” is a kicker, “WHO WE ARE” is an eyebrow.

8 · Rules & gotchas

Each of these cost real debugging time. The symptom is listed because that is how you will meet it again.

Hard rules

  • A literal font-size in a block is a bug. Use a role token. The PING block set currently has zero — keep it that way.
  • Never re-declare .container-custom in a scoped style. Symptom: the header stops lining up with the content.
  • Breakpoints are 768px and 1024px. Nothing else. (We had 12, including both 767 and 768, and both 992 and 991.98.)
  • One exception: the header collapses at 1200px (BlockSiteNav, @media (max-width: 1199px)). Six nav links + Subscribe + the orange pill + the wordmark need ~1066px of row, and .container-custom does not hand that much back until the viewport is ~1130px. At 1024 the desktop header still rendered — it just squashed the logo to 77px to do it, because the global img { max-width: 100% } lets an image shrink to nothing inside a 1fr grid track. Do not copy this breakpoint into a block; it is about the header's own contents, not about the page.
  • Don’t restate heading sizes in a block media query — :root already shrinks the scale at 768px.
  • Never prettier --write — ESLint is the only formatter here.

Motion

Pick a duration by role, exactly like a --fs-*. A literal duration or easing curve inside a block is a bug. There is one easing curve, --ease-out, and one kill switch — the prefers-reduced-motion block at the bottom of theme.css, which zeroes every animation and transition site-wide. Nothing on this site loops forever.

  • A coloured band never fades — only what is inside it moves. Put the reveal on the inner container (.mh-inner, .wg-grid), never on the <section> that carries the background. Symptom if you get this wrong: the band flickers and the page height jumps as it fades.
  • Above the fold = CSS. Below the fold = v-reveal. A hero animates with a plain animation that runs at first paint. Never v-reveal a hero — if hydration is slow the copy flashes visible → hidden → in again.
  • The hidden state is never in the SSR HTML. v-reveal (app/plugins/reveal.ts) writes data-reveal at mount, so a visitor with JavaScript off, or a crawler, always gets the finished page. Do not bake opacity: 0 into a block's own CSS.
  • Register directives on the server too. The plugin is reveal.ts, not reveal.client.ts. Vue's SSR renderer throws Cannot read properties of undefined (reading 'getSSRProps') on a directive the server has never seen, which 500s every page that uses it. Only mounted does any work, and mounted never runs during SSR.

The three directive forms, and when each is right: 

v-reveal           <!-- this element fades + rises -->
v-reveal.stagger   <!-- each DIRECT CHILD does, --reveal-stagger apart -->
Only ever hide with opacity, never with clip-path. A clip-path shrinks the element's visible area to zero; IntersectionObserver then measures zero intersection and the callback that would un-hide it never fires. The hidden state prevents its own reveal, permanently.

Symptom: the art flashes in for a few milliseconds on load (the server-rendered markup, which is unclipped) and then vanishes the instant Vue hydrates and applies the hidden state. Meanwhile ordinary v-reveal content on the same page reveals normally, because it hides with opacity — which is exactly the clue that separates the two.

This is why decorative curves are not scroll-triggered.

Decorative curves

Never put an <svg> in a block for a decorative curve. Every curve on the site is one component, <ThemeCurve>, drawing a shape from utils/curves.ts. Blocks used to own their own SVG, their own viewBox, their own preserveAspectRatio and their own copy of the keyframes — eleven blocks, eleven sets of numbers — and that is precisely how the theme ended up with the same path rendering 150px thick on /brands and 130px on a portfolio page.

The rule: the box never decides the drawing. One shared unit does — 1 curve unit = min(1, 100vw / 1440) px. useCurveFit measures the element and computes the viewBox backwards from that unit, so the viewBox always carries the element's own aspect ratio and the artwork cannot be squashed. Two things follow:

  • Nothing is ever stretched. A taller band does not fatten the curve, it just hands it more empty room.
  • A ribbon is the same weight everywhere. --curve-thickness (130) units renders the same number of pixels on every page at a given screen width, by construction.

So how does a curve reach the screen edges? It gets longer, never bigger. Above 1440px the unit stops growing, the measured viewBox becomes wider than the artwork, and the engine extends the shape. Two mechanisms, one per family:

  • Splines — a centre line we draw ourselves and stroke at the shared weight. To lengthen one, its end points are carried outward along their own tangents until they are off the canvas. Stroking is also what keeps a diagonal band exactly as thick when it steepens.
  • Outlines — ribbons exported from the design tool as filled shapes. Their thickness is baked in, so they cannot be re-drawn — but each is cut off flat where it ran past its own art board, and curve-art.ts records those cuts with the slope of the edge either side. Each edge is continued along its own tangent, so the join stays smooth instead of kinking. 
<!-- A full-bleed curve: ThemeCurve fills its parent, so position the PARENT. -->
<section class="xx">                       /* position: relative; overflow: hidden */
  <ThemeCurve shape="converging" reveal="left" />
</section>

<!-- A curve that should only cover part of a band: wrap it. -->
<div class="xx-curve">                     /* position: absolute; right: 0; width: 50% */
  <ThemeCurve shape="shield-tick" reveal="none" />
</div>

Never set a width, a height or an aspect-ratio on the curve itself, and never add a per-breakpoint override for one — that is the box deciding the drawing again. If a curve looks wrong at some width, the shape's place in curves.ts is the knob, not CSS.

Animating a curve

Do not write the keyframes. ThemeCurve owns them; pass reveal and pick the direction the ribbon travels (left, right, up, down, fade, none).

Do not put an animation on a shape inside <defs>. Elements in <defs> are never rendered, and browsers do not advance animations on unrendered elements. Symptom: getAnimations() reports the animation as running but currentTime stays at 0 forever, and the art simply never appears. 
/* What `reveal` expands to, in ThemeCurve — no scroll trigger, no observer.
   inset(top right bottom left) — each number is how far IN from that edge.
   Ribbon travels left → right, so clip 100% from the RIGHT and open it. */
.theme-curve--left { --curve-from: inset(0 100% 0 0); }
@keyframes theme-curve-draw { from { clip-path: var(--curve-from); } }
/* `backwards`, not `forwards`: the from-state is held only during the delay,
   so the END state is the element's own style — no clip. A curve whose
   animation never runs is therefore VISIBLE, not permanently invisible. */
The edge you clip FROM is the one the reveal grows AWAY from. This is the easy one to get backwards — we shipped all four vertical curves inverted first time. Verified by hit-testing a plain 400px box:

inset(0 0 50% 0) — bottom inset 50% — leaves the TOP half showing, so inset(0 0 100% 0) → inset(0 0 0 0) is collapsed at the top and opens downward.
inset(50% 0 0 0) — top inset 50% — leaves the BOTTOM half showing, so inset(100% 0 0 0) → inset(0 0 0 0) is collapsed at the bottom and opens upward.

Direction follows the path, so read the shape before choosing an axis. A ribbon that rises (rising-line) takes reveal="up"; one that descends (crescent) takes reveal="down". A curve that spans the whole document (page-snake) takes reveal="fade" — a wipe across it would be almost entirely off-screen, so there is no version of "drawing" it a reader can perceive.

The small <circle> and <path> icons (.wu-tick, .cg-icon) are not curves. They are real strokes with their own weights and they use the dash trick — with pathLength="1" so the maths is just 1 → 0. Leave them alone.

Layout traps

  • A max-width tuned for the old font size. Bit us four times (“Years of Experience”, “Aggregated…”, the step titles, the stats descriptions). Symptom: text wraps oddly or spills its box after you bump a size. Rule: change a font size → re-check every cap on that element.
  • min-width: 0 on flex/grid children. A flex item won’t shrink below its content’s min-width, so the longest label silently widens its column. Symptom: “equal” columns aren’t equal.
  • A gapped grid can’t take 60% / 40% — that totals 100% + the gap and overflows. Use fr, and wrap in minmax(0, …) so a long word can’t blow the track out.
  • Percentage heights need a definite parent height. align-items: flex-end leaves the child’s height as content, so % resolves to nothing. Use stretch.
  • container-type goes on the PARENT. It makes an element a container for its descendants — an element cannot read its own cqw.

CSS facts that look like bugs

  • left/top do nothing on a static element. They need position: relative/absolute.
  • Absolute offsets measure from the padding box. Adding padding to the parent will not move an absolutely-positioned child — change its top.
  • Form controls don’t inherit the page font. theme.css opts them in globally, but only font-family — set font-size yourself or you get 13.33px.
  • Transforms don’t apply to inline elements. (Flex/grid children are blockified, so they’re fine.)

Content vs CSS — the workflow difference

CSS changes hot-reload. Edit a .vue style and just look at the page.

Content changes do not. Copy lives in apps/api/fixtures/ping/pages.json. After editing it you must reseed — and the seeder does not invalidate the cache, so you must also flush it or the page serves the old copy for up to 5 minutes: 
pnpm --filter @cms/api seed:fixtures ping --tenant=newping
# then flush the stale page cache (Dragonfly, redis-compatible):
docker exec new-pingwebsite-dragonfly-1 redis-cli --scan --pattern 'cache:page:*' \
  | while read -r k; do docker exec new-pingwebsite-dragonfly-1 redis-cli DEL "$k"; done
Server-side code (a block’s .ts, a template, a part) needs a @cms/blocks rebuild + an API restart: pnpm verify:theme then touch apps/api/src/index.ts.

Editor-controlled line breaks

To break a heading at a chosen word, put a real newline in the fixture copy and set white-space: pre-line — don’t hard-code a <br> (that would force v-html and turn editor copy into markup). 

// pages.json
"title": "Some of our Growth\nPartners to Top Brands"

/* the block */
.xx-title { white-space: pre-line; }

Verify before you call it done

  • pnpm verify:theme → must be GREEN. It proves structure, not pixels — it never mounts the .vue.
  • pnpm check:theme-scope → must be clean.
  • Then look at the page. The screenshot tool times out on this site, so assert with getComputedStyle in the browser instead of trusting your eyes.
  • Motion cannot be verified in an automated browser pane. It reports document.visibilityState === 'hidden', so requestAnimationFrame never fires, document.timeline.currentTime is frozen at 0, and IntersectionObserver callbacks are never delivered — even for an observer you create yourself on document.body. Everything v-reveal touches therefore looks stuck and invisible. That is the harness, not your code. Check the two halves separately: drive the CSS with document.getAnimations().forEach(a => a.finish()) or by setting data-reveal="in" by hand and asserting where it lands, and confirm the JS half by checking the attribute was applied at all. Real playback needs a real browser window.
